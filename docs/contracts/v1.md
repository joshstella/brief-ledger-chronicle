# Contract v1 — the briefs convention

**Status:** current

What this repository guarantees about the structure of `docs/briefs/`. See
[README](README.md) for how to read a clause and what a Contract will not do.

## Scope of this version

Version 1 covers the structure of `docs/briefs/` only. It says nothing about process — which
skills gate `main`, whether tests are required — even though those rules are stated in the
present tense elsewhere in this repository. That silence is deliberate. This document does
not claim to be the only place rules live.

**Every clause in version 1 is checked by `tools/validate-briefs.sh`.** The script travels
with this document, so a repository that holds the Contract also holds the check. No clause
carries a review date, because none is unchecked and a CI run is a better date than a hand
stamp.

Two limits on that claim, stated because a validator implying coverage it lacks is the
defect this document exists to prevent.

`BRIEFS-8` is checked but never blocks. The validator prints it and exits zero, because the
clause is `[judgment]` and a retired serial is a question for a human.

**Holding the script is not running it.** Where no continuous integration job calls it,
these clauses are exactly as reliable as the people who follow them.

**Every clause in version 1 is scope `both`**, so in this version the field discriminates
nothing. It is stated per clause anyway, because it starts to carry weight the moment a
second namespace arrives, and because a field introduced later reads as a change in meaning
rather than a change in coverage.

## Clauses

### BRIEFS-1 — entries are briefs or known non-numbered files

`[defect]` · scope `both` · checked: `tools/validate-briefs.sh`

Every entry in `docs/briefs/` is either a `NNNN-slug/` folder or a known non-numbered entry
(`_drafts/`, `README.md`).

### BRIEFS-2 — slug and serial shape

`[defect]` · scope `both` · checked: `tools/validate-briefs.sh`

Slugs match `^[a-z0-9-]+$`. Serial prefixes are exactly four digits.

### BRIEFS-3 — serials are unique

`[defect]` · scope `both` · checked: `tools/validate-briefs.sh`

No two folders share an `NNNN`.

### BRIEFS-4 — every brief folder holds a brief

`[defect]` · scope `both` · checked: `tools/validate-briefs.sh`

Every `NNNN-slug/` contains a `brief.md`.

### BRIEFS-5 — the identity line is well formed

`[defect]` · scope `both` · checked: `tools/validate-briefs.sh`

Each `brief.md` carries an identity line whose `Serial` matches its folder, with `Created`
(ISO-8601 UTC), `Author` (email-shaped), and `Depends on`.

### BRIEFS-6 — no dangling dependencies

`[defect]` · scope `both` · checked: `tools/validate-briefs.sh`

Every `Depends on: #NNNN` references an existing serial.

### BRIEFS-7 — drafts are unnumbered

`[defect]` · scope `both` · checked: `tools/validate-briefs.sh`

Nothing in `_drafts/` has a four-digit-prefixed name.

### BRIEFS-8 — serials are contiguous

`[judgment]` · scope `both` · checked: `tools/validate-briefs.sh` (never blocks)

Serials run contiguously from `0001`. A gap is surfaced, not blocked: a removed brief
legitimately retires its number.

## Known limitation — concurrent filing

`create-brief` computes the next serial from the local `docs/briefs/` directory, then writes
the folder. A second step increments until that path is free on this checkout. That step
closes a stale read on one machine. It does not close two machines.

Two checkouts each read their own tree. Each passes its own guard. Each can claim the same
serial, which would break `BRIEFS-3`. Solo, this never fires. Two people filing two briefs
can hit it.

The named mechanical fix is allocation against the pushed remote. That is not built, and it
would not close the race by itself: `create-brief` does not publish the serial, so two
checkouts can fetch the same `origin/main` and still pick the same next number. Closing it
for real means publishing a reservation before the other reader runs — a push at filing
time. This project does not do that.

**Recovery:** the first of the colliding briefs to land on `main` keeps the serial. The
other renumbers before it merges: folder name, identity line, inbound `Depends on`, ledger
`blc/1` line, PR title. Do that on the losing branch, not by rewriting history on `main`.
